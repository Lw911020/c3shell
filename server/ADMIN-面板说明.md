# c3shell 后台面板说明（v2 · 带登录 + 美化）

## 1. 需要设置的变量（Worker → Settings → Variables and Secrets）

| 变量名 | 作用 | 必需 |
|---|---|---|
| `CARDS` | KV 命名空间绑定（存卡密/绑定/设备/反馈/赞赏） | ✅ |
| `TOKEN` | 接口口令（`/mint` 免登录发卡用），同时用作登录 Cookie 的签名密钥 | ✅ |
| `ADMIN_USER` | 后台登录名（不填默认 `admin`） | 建议 |
| `ADMIN_PASS` | 后台登录密码（**不填则后台只能靠 `?token=` 进入**） | ✅ |

## 2. 两个入口

- **正常登录**：浏览器打开 `https://api.jiangdl.icu/admin` → 出现登录页 → 输入 ADMIN_USER / ADMIN_PASS → 进入后台（Cookie 会话，7 天，退出按钮可登出）。
- **免登录**：`https://api.jiangdl.icu/admin?token=<TOKEN>`（兼容旧用法，适合自己手机存书签）。

## 3. 面板里有什么

- **概览卡片**：在线（10 分钟内有心跳）/ 累计设备 / 今日活跃 / 卡密总数 / 已使用 / 反馈数 / 赞赏笔数与合计金额
- **发卡**：填计划、天数、数量、每卡可绑台数 → 点「生成卡密」→ 页面上直接列出新卡密
- **设备**：设备ID / 在线状态（绿=在线） / 绑定卡密 / 版本 / 心跳次数 / 首次与最近时间
- **卡密**：计划 / 到期（过期显示红标） / 台数 / 已绑数量 / 创建时间，带**删除**与**解绑**按钮
- **绑定关系**：卡密↔设备对照表（一眼看出哪张卡绑了哪台机器）
- **反馈**：时间 / 设备 / 正文 / 版本 / 联系方式，**带截图缩略图**与**日志尾部**（可直接展开看）
- **赞赏**：时间 / 设备 / 金额 / 版本 / 联系方式，标题上显示合计金额
- 每个区都有 **导出 CSV** 按钮（卡密 / 设备 / 绑定 / 反馈 / 赞赏）
- 页面 **每 60 秒自动刷新**（正在输入时不刷新，不会打断你打字），手机浏览器也能正常看

## 4. 安全建议

- `ADMIN_PASS` 用 12 位以上；它和 `TOKEN` 都建议按「密钥/加密」类型保存。
- 不要在群里发 `?token=` 的链接（等于把后台口令发出去）；正常用登录页即可。
- 想强制所有人走登录页：把 `TOKEN` 换成一个更长的随机串（它同时是会话签名密钥，改了等于让所有旧会话失效）。
- 卡密默认「一台机器一张卡」，需要多机就把「每卡台数」填大。

## 5. 换上 v2 的部署动作

1. 控制台 → 你的 Worker → **Edit code** → 全选删除 → 粘贴新版 `worker.js` → **Deploy**
   （编辑器若不吃模块语法，就粘贴 `worker-legacy.js`，功能一模一样）
2. **Settings → Variables and Secrets** 里补上 `ADMIN_USER`、`ADMIN_PASS`（`CARDS`、`TOKEN` 应已存在）→ 保存后**再 Deploy 一次**
3. 打开 `https://api.jiangdl.icu/admin` 用登录名/密码登录

> 已经发出去的卡密、已有的设备和反馈都在 KV 里，**升级面板不会丢数据**（键名格式没变）。

## 6. v2.1 新增：卡密续期 + 设备历史

### 6.1 卡密续期
- 位置：后台「卡密」表每一行末尾 → **续期** 按钮前有个天数输入框（默认 365）。
- 规则：从**当前到期时间**往后加（没过期就叠加；已过期或永久卡则从**现在**起算）。
- 把天数填 **0** → 该卡设为**永久**。
- 也可用命令行：
```bash
# 续 30 天 / 设为永久
curl "https://api.jiangdl.icu/admin/act?do=renew&code=C3-XXXXXXXXXXXX&days=30&token=<TOKEN>"
curl "https://api.jiangdl.icu/admin/act?do=renew&code=C3-XXXXXXXXXXXX&days=0&token=<TOKEN>"
```

### 6.2 设备历史时间线
- 位置：后台「设备」表每一行 → **历史** 按钮 → 进入 `admin/device?id=<设备ID>`。
- 设备详情页显示：在线/离线、心跳次数、事件数、版本、首次与最近时间、绑定卡密，
  **持有卡密表**（含到期时间），以及**事件时间线**：
  - `verify` 激活（含卡密、计划、到期时间）
  - `feedback` 反馈（含正文摘要）
  - `appreciate` 赞赏（含金额）
  - `heartbeat` 心跳（含功能、模式）
- 事件存成 KV 键 `hist:<设备ID>:<时间>-<随机>`，与卡密/反馈数据互不影响。

### 6.3 写入量（免费额度 1000 次写/天）
- 激活、反馈、赞赏：各写 1 条事件。
- 心跳：**同一台设备最多每 6 小时写 1 条**（其余心跳只更新 `dev:` 记录），也就是每台设备最多 4 条/天。
- 粗算：50 台设备日常使用（每天各 1 次激活 + 4 次心跳事件）≈ 250 写/天，离免费上限还很远。
